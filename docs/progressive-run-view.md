# Progressive attack-run map

The user reopened the map's visibility behavior on 20 November 2026: omit infrastructure not probed or used, begin with visible entry surfaces and expand as the run progresses. This is a focused change to presentation in phases 4–6, preserving controls, styles, concurrency, engine inputs and causal outcomes. It supersedes the earlier UI freeze only for this requested filtering/reveal behavior.

The renderer builds a read-only discovery plan from the completed simulation trace. Following the user's clarification, initial visibility comes exclusively from the estate's external entry surfaces, independent of attacker choice, defense choice or future actions. Both attacker profiles therefore start with the same assets in the same positions. Known public surfaces remain as context even if a particular attacker does not use them. Unseen internal infrastructure stays excluded until its first modeled probe starts, before the outcome is shown. This is a trace-derived demonstration of discovery, not a new reconnaissance engine or a measurement of real network traffic. The run is still simulated against the complete estate with its original exploration budget.

The final map retains successful access, prevented attempts, local persistence/encryption, and scheduled unsuccessful probes. An in-flight action canceled by containment still counts as probed. Policy exclusions, pure revisits, zero-duration eligibility checks, invalid routes or missing source capabilities, and jobs canceled before starting do not disclose new targets. A successful starting foothold is retained even if it takes zero modeled seconds. Control events alone do not reveal an otherwise unused asset. Only relationships actually used by retained events are drawn, including unsuccessful branches; unrelated connections between visible nodes remain absent.

New nodes append within their existing trust-layer lanes; already visible nodes retain their positions as discovery grows. The canvas height expands with discovered rows rather than reserving space for the whole estate. Replay resets discovery; Results reveals the completed trace; resize reconstructs the same view at the current modeled time. Each attacker/defense selection gets its own discovery plan on the unchanged shared estate.

Before an action is observed, a visible node exposes its asset identity and interface rather than its full unobserved finding or credential list. Completed events add their technique, finding, source and actually recovered credentials. Search and keyboard focus apply only to revealed assets. Untouched decoys and illustrative branches are not exposed as attacker discoveries.

The full estate remains available to the simulation and saved comparison state. The same visibility rules apply to the main map, embedded comparison and focused path views. Capture planning retains failed probes and real starting access rather than pruning to successful breach paths. Existing node states and final summaries continue to report observed protected reads, persistence, encryption, alerts and containment.

Checks: `node scripts/test-run-discovery.cjs`, `node scripts/test-capture-plan.cjs`, browser replay/discovery checks, and `scripts/test-discovery-comparisons.cjs` cover start-time visibility, growth, failed branches, containment, no future search leaks, resizing, completed filtering, embedded frame fitting and unchanged engine history. Existing model and Windows fleet checks remain applicable.
